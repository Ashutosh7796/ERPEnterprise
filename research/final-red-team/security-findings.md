# Enterprise ERP Red-Team Security Findings & Vulnerability Matrix

## 1. Vulnerability Assessment Summary Table

| ID | Severity | Attack Vector | Root Cause | Affected Component | Impact | Remediation Applied | Permanent Regression Test | Status |
|:---|:---:|---|---|---|---|---|---|:---:|
| **SEC-01** | CRITICAL | Cross-Tenant TenantId Injection via Body/Query | Client parameter trusting | Security Filter & Tenant Line Interceptor | Potential cross-tenant data leakage | Enforced server-authoritative tenant extraction from authenticated JWT/SecurityContext only; request parameters ignored | `FullErpRedTeamAdversarialStressTest.testAttack01_TenantIsolation_DirectTenantIdParameterTampering` | **RESOLVED** |
| **SEC-02** | HIGH | Multi-Tenant Switching to Inactive Membership | Missing membership status validation on context switch | `UserTenantMembershipMapper` / `MultiTenantService` | User could access resources of suspended tenant | Added strict `status == 'ACTIVE'` membership validation prior to token issuance | `FullErpRedTeamAdversarialStressTest.testAttack03_MultiTenantSwitching_SuspendedOrDeletedMembershipRejected` | **RESOLVED** |
| **SEC-03** | HIGH | Legacy Username `admin` Privilege Escalation | Hardcoded string check for username `"admin"` | `AuthorizationService.isSuperAdmin` | Customer tenant user named `admin` inherited platform governance rights | Super Admin check decoupled from username; bound strictly to `authorityDomain == 'PLATFORM'` and Role ID 4 | `FullErpRedTeamAdversarialStressTest.testAttack06_RBAC_LegacyAdminUsernameWithoutPlatformRoleBlocked` | **RESOLVED** |
| **SEC-04** | HIGH | Support Specialist READ_ONLY Mutation Bypass | Missing server-authoritative action guard | `SupportAccessService` & `SecurityFilter` | Support operator in read-only mode could issue POST/PUT/DELETE requests | Integrated HTTP method / action classifier blocking all mutations when session access mode is `READ_ONLY` | `FullErpRedTeamAdversarialStressTest.testAttack10_Boundary_SupportSpecialistReadOnlyActionBlocked` | **RESOLVED** |
| **SEC-05** | HIGH | High-Concurrency Quota Overrun Race Condition | Non-atomic quota check-then-act | `TenantSubscriptionService` / User creation | Multiple concurrent requests overran quota limit | Implemented atomic database check and row-level pessimistic locking on tenant seat quotas | `FullErpRedTeamAdversarialStressTest.testAttack16_QuotaConcurrency_SimultaneousUserCreationRaceConditionBlocked` | **RESOLVED** |
| **SEC-06** | MEDIUM | Intermediate Provisioning Failure Leaving Zombie Records | Non-transactional multi-stage bootstrap | `TenantProvisioningOrchestrator` | Orphaned tenant, depot, or organization rows on failure | Enclosed complete 10-stage provisioning pipeline in `@Transactional(rollbackFor = Exception.class)` | `FullErpRedTeamAdversarialStressTest.testAttack18_ProvisioningChaos_FailureAtEveryStageTriggersCompleteRollback` | **RESOLVED** |
| **SEC-07** | MEDIUM | Invalid Tenant Lifecycle State Transition | Unvalidated state mutations | `TenantLifecycleService` | Archived or soft-deleted tenants could be directly reactivated | Formal 7-state finite state machine with legal transition lookup table (`LEGAL_TRANSITIONS`) | `FullErpRedTeamAdversarialStressTest.testAttack20_Lifecycle_IllegalStateTransitionsRejected` | **RESOLVED** |
| **SEC-08** | MEDIUM | Stale Redis Sessions Surviving Tenant Suspension | Incomplete session invalidation | `TenantLifecycleService.suspendTenant` | Suspended tenant users retained active sessions | Implemented immediate Redis session key eviction on administrative suspension | `FullErpRedTeamAdversarialStressTest.testAttack21_Lifecycle_SuspensionEvictsRedisSessionsImmediately` | **RESOLVED** |
| **SEC-09** | MEDIUM | Cross-Tenant SSE Event Leakage | Shared SSE broadcast bus | `SupportNotificationService` | Tenant A could receive Tenant B real-time notifications | Partitioned `tenantEmitters` Map indexed strictly by `tenantId`; isolated unicast dispatch | `FullErpRedTeamAdversarialStressTest.testAttack23_SSE_ZeroCrossTenantEventLeakage` | **RESOLVED** |
| **SEC-10** | LOW | Sensitive Token Logging in SSE Hook | Unfiltered console logging | `useSSE.ts` | Bearer token visible in browser dev console | Removed all sensitive token and payload logging; sanitizing debug statements | `phase14_15_16_security.test.ts` | **RESOLVED** |
